# Decision desk iteration — 8 September 2026

The review covered the current saved housing scenario and its 4,745 stored listings. It found
and corrected metric sorting, unclear statistical populations, discarded drafts, comparison
request races, inaccessible phone comparison controls, and repeated work in list requests.

## Changes

- The first screen now prioritizes results. Stay settings and inventory evidence expand on
  demand; saved dates and the budget remain visible, with a direct link to matching rooms.
- Explicit expense, cash, space, transit and geographic sorts follow the chosen metric across
  evidence tiers. Missing values sort last. The default retains evidence-first ordering.
- Filtered statistics separate complete expense quotes from incomplete known minimums. Each
  distribution reports the median, observed range, sample size and unknown count. Room area,
  complete cash before keys, route coverage and common unresolved cost questions are included.
  Reserved and dismissed listings are outside potential-match statistics and the default view.
- Filters, search, chart metric, tab and pagination survive reload through the URL. Comparison
  selections survive reload in tab session storage. A visible tray supports removing individual
  rooms, clearing the selection and jumping to the comparison.
- Comparison cancellation and sequence checks prevent obsolete responses from overwriting the
  latest selection. Unchanged comparisons, charts and maps are reused on pagination.
- Scenario drafts have a visible indicator and Revert. Reloading data and saving pins preserve
  unapplied scenario edits. Pin confirmation, cancellation and persistent undo still apply.
- Quote and room-fact updates use labeled fields with provenance. Blank inputs retain existing
  values; zero must be explicit. Missing-cost questions can be resolved individually. Advanced
  JSON remains available for less common facts and estimates.
- Phone results stack into labeled rows with costs, room area, route coverage and comparison
  controls visible without horizontal scrolling. Map popups identify incomplete prices as floors.
- Pure calendar calculations and policy hashes use bounded caches. Extra departure scenarios
  are deferred until details, comparisons or full JSON exports request them. List responses
  omit individual route observations, which remain available in room details and JSON exports.

## Measured performance

Loopback HTTP measurements used the same saved preferences, 4,745-record snapshot, and
`GET /api/decision?metric=distance`. Each sample contained one cold request after server restart
and 15 warm requests. These are local observations, not a statistical performance guarantee.

| Measure | Before | After |
| --- | ---: | ---: |
| First request | 1,064.64 ms | 601.26 ms |
| Warm median | 5.33 ms | 3.66 ms |
| Warm sample p95 | 5.72 ms | 5.77 ms |
| Response body | 193,180 bytes | 134,519 bytes |

The cold request improved about 44%, the warm median about 31%, and the payload about 30%.
Tail latency did not materially improve in this small sample. Browser checks also confirmed
that table pagination retained the existing chart node rather than reconstructing it.

## Data limits

The current view has 68 potential matches: 59 geographic chart positions (one complete case
and 58 provisional) and nine listings without enough data for a point. Room area is known for
19; complete cash before keys and complete office route sets are known for none. These gaps
are shown explicitly and prevent stronger conclusions. Complete quotes, confirmed office
entrances and fresh observed routes remain necessary to improve decision confidence.
